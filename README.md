# Clinical PhD Index

Open `index.html` for the static coverage preview, or serve this folder with `python3 -m http.server 8000`. Use `data-quality.html` to see the dated dataset, review queue, and the status of the 50-faculty recall audit. The preview keeps program pages available while the leaderboard awaits validation.

## Evidence pipeline

The **Review program rosters** workflow runs monthly and can also be dispatched on demand. It checks all program entries and uploads the source scan, matched institutional profiles, staged OpenAlex records, and public bibliography leads for the audit sample. Staging requires a confirmed official profile and a confidently resolved OpenAlex ID using a linked ORCID or agreeing name, affiliation, and research topics. The artifact contains evidence for role and coverage review. The production dataset receives only reviewed faculty and publication attributions.

1. **Program inventory.** `data/programs.json` preserves the 193 supplied program entries as a coverage checklist, plus candidates from official directories. The file contains program-level public information. The workbook and its application or faculty-fit notes are excluded. Each directory membership or accreditation status carries its own evidence. The seed includes a dated APA historical extract and the APA live search result, plus a CUDCP public directory capture reconciled to known programs. Unmatched CUDCP rows and international and doctoral-degree eligibility remain under review. Run `pipeline/directories.py` to collect PCSAS and CPA entries or pass normalized APA/CUDCP exports with `--apa-export` and `--cudcp-export`. A normalized export requires `name`, `degree`, `clinical`, `status`, and `source`. Review merges and degree or activity status before accepting candidates into the production inventory.
2. **Faculty.** Run `python pipeline/rosters.py --cache .cache/rosters --output review/roster-candidates.json` to collect candidate names and evidence URLs. Candidates still require source-specific role and completeness review. Record accepted people in `data/faculty-input.json`, with stable IDs, aliases, lab/CV and ORCID sources, research areas, and dated tenure-track or research-track appointments. Use `rosterReview: "complete"` only after checking the whole clinical roster. The monthly GitHub workflow checks recorded roster pages and uploads changes for manual review.
3. **Identity and works.** Set `OPENALEX_API_KEY` in the environment for cursor pagination. `SEMANTIC_SCHOLAR_API_KEY` is optional and useful for higher request limits. Review uncertain profiles in `data/review-queue.json`, then record accepted OpenAlex IDs and reasons in `data/reviewed-identities.json`. `pipeline/sources.py` pulls OpenAlex works by ID, cross-checks PubMed via E-utilities, and adds DOI-linked Crossref/Semantic Scholar evidence. Crossref also supplies PsyArXiv candidates corroborated by ORCID. Public lab and CV records can be transcribed into `data/reviewed-works.json` using the same normalized work format, with `provenance` naming the original Lab or CV URL, an independently reviewed byline and `people` keyed by faculty ID. These imports support publisher-confirmed `firstPositions`, `lastPositions`, and `publisherByline: true`. The full job also runs Crossref author discovery by ORCID and Semantic Scholar author discovery for manually verified IDs in `semanticIds`. The diagnostic build caps DOI lookups and skips those full discovery queries. Publisher JATS metadata can corroborate documented co-first and co-senior authorship. No Google Scholar or PsycINFO collection.
4. **Audit.** The initial 50-person calibration sample, five-year window, and publication snapshot fingerprint are frozen in `data/calibration-plan.json`. Use `python pipeline/build.py --cache .cache/publications --network --audit-stage calibration` to measure updated snapshots against that sample. Save full independent bibliographies in `data/audit-references.json` by faculty ID, including the source, verified window, completeness, works, and explained exclusions. Reference works require title, publication date, kind, DOI when available, and publication-date evidence. Preserve initial comparisons and diagnosed misses in `data/calibration-history.json`. After verifying the eligible current rosters, archive the latest calibration report as `data/calibration-report.json` and draw a fresh sample with `--audit-stage holdout --audit-seed NEW_SEED --calibration-report data/calibration-report.json`. The holdout excludes faculty with completed calibration references and those used in the diagnostic checks. Calibration can stop once it has served its purpose. The published estimate requires a complete set of five-year references for 50 holdout faculty.
5. **Build and deploy.** `pipeline/build.py` writes `publication-data.js` and faculty, publication, review, and recall data in `data/`. Run `python -m unittest discover -s pipeline -p 'test_*.py'`. In the approved GitHub repository, set Pages source to GitHub Actions. The Pages workflow deploys the static site and dataset exports. The refresh workflow uploads a reviewable artifact and leaves the public snapshot unchanged until reviewed. Set `--report-target` to the published repository's `https://github.com/OWNER/REPO/issues/new` URL only if public correction drafts are desired. The default correction form downloads a local draft.

## Attribution

For roster verification, `currentRosterReview` records the scope, date, and role decisions for the current faculty list. `rosterReview: "complete"` is reserved for programs where the current roster and relevant historical appointments have both been checked. Dates recorded as `onRosterBy` establish only that the person was listed by that date.

The Actions refresh defaults to full publication retrieval. Its primary mode queries OpenAlex for the expanded roster and carries forward evidence for unchanged, manually resolved faculty. The data quality page reports the calibration sample and independent CV checks separately from the holdout. Evidence for a byline correction is stored at the individual DOI in `data/reviewed-works.json`. A correction to one byline leaves the other records on the OpenAlex profile untouched.

The default window is exactly ten years before the build date. Journal articles and reviews use publication type as a peer-review proxy when item-level evidence is unavailable. Preprints are displayed separately. The scorer splits a paper across authors, then splits an author's credit across independently verified simultaneous clinical appointments if applicable. Weighted mode uses the outer positions for papers over 50 authors. Unknown publication or appointment evidence is flagged for review. A change in program affiliation does not move previously credited work.
